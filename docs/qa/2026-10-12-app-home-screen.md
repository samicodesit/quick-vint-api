# Optional app home-screen support

The owner approved a lean installable web app with no extra install popups. The enabled app and its auth callback share a small head component: an AutoLister manifest, existing inspected brand icons, Apple home-screen metadata and the app's existing background color. A single inline listener cancels automatic `beforeinstallprompt` behavior. Installation remains available through the browser's own menu. No install CTA, timer, dialog, service worker, offline page cache, push notifications, dependency or backend request is added.

The manifest has a stable `/app` identity and start URL. Its explicit `/app` prefix scope preserves the existing bare app route, auth callback and checkout query returns without changing URLs or including the marketing homepage. Existing root manifest assets are reused as ordinary icons, not advertised as maskable artwork. The marketing site's manifest is unchanged.

The multiple-item processing tab has a small static New badge above it in both item and batch entry views. It shares the existing brand color and leaves the layout height and 44px tab target intact. The badge is decorative and does not change the button's accessible name.

The browser tests failed first on absent manifest metadata and the absent badge. The install check then passed against actual locally served app HTML: Chromium parsed the manifest without errors, decoded the 192px/512px icons, suppressed a cancelable install event, found no registered workers/caches/open overlay, and confirmed the callback's shared manifest. The 22-step real browser app journey passed, including badge geometry at 320/390/768/1440px, both modes, draft persistence, quota/paused prompts, bearer checkout retry/cancellation and callback recovery. Fixtures do not generate real listings, buy anything or change customer data.

Physical iPhone/Android installation, OAuth handoff and payment return from an installed home-screen window remain untested. Browser-mode tests cannot prove those OS-level handoffs. iOS may keep installed-app storage separate from Safari, so existing local Safari drafts are not promised to migrate on installation. Generation and reloading the app still require internet; the existing open-page local editor can save offline edits.

Final guarded push and live metadata acceptance are recorded after publication.
