## Findings and repairs

The baseline short-phone regression recorded twelve visibility or geometry findings. Both copy actions and the title were below the fold at 360/390px. Single-item generation was below ten photos. Batch generation, pause and resume were below twelve items. Single-item progress moved the navigation. A separate save-error test also failed because Retry save followed the description. Fresh screenshot review found a disabled generation footer partially covering photo recovery controls. Sign-in error copy offered a new code without a direct resend control.

- Mobile review now uses a compact horizontally scrollable photo strip, bringing the title and both copy controls into the first 640px viewport. Desktop retains the large cover column.
- Preparation uses a pinned mobile action area with bottom clearance. Single and batch progress replace the action inside the same area. The last photo and item can scroll fully above it. Active photo selection retains its own Create item footer.
- Batch progress keeps the title unchanged. Moving the queue into its preparation host prevents navigation displacement. Text-panel entrance uses opacity without creating a temporary containing block for the fixed footer.
- Retry save sits beside save status, with a 44px icon control and an accessible name. The error explanation remains above the workspace.
- A failed photo gives Retry and Remove priority. The disabled Generate footer is hidden until recovery, and active generation progress remains available.
- Resend code reuses the existing magic-link endpoint, preserves the email, clears the old code and disables itself during requests or verification. All sign-in checks intercept requests; no email was sent by this audit.

No endpoint, database, entitlement, generation or persistence contracts changed. Clipboard fallback, autosave, version conflicts, photo grouping, item overrides and manual Listed semantics remain covered.

## Coverage limits

This is deterministic Chromium and in-app-browser QA. Physical iOS/Android devices, Safari, native camera/HEIC behavior, physical QR scanning, on-screen keyboard appearance, native zoom, live authentication, billing/provider integration and marketplace publication remain unverified. CSS zoom does not establish native browser zoom behavior. A partial bulk-delete failure and a conflict while editing batch-row settings were not separately injected; existing single-item retry/conflict and exact selected deletion are covered.

Temporary capture matrices remain in `/tmp/autolister-mobile-final` and baseline audit folders. They are not production data. Earlier cleanup was blocked by automatic approval review, so that blocked recursive deletion was not repeated through another shell.
